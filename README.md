# PLAYROOM / 小遊戲集合所

可自行部署的小遊戲平台。玩家可以免登入遊玩，也可以註冊玩家帳號；管理員從公開 GitHub Release 匯入靜態網頁遊戲。遊戲可獨立開發、更新及回退，不需重新建置平台。

## 帳號與角色

大廳右上角提供註冊及登入。註冊後自動登入，帳號固定為 `player`，不能透過註冊指定角色。後台入口、頁籤及 API 都依角色限制：

| 角色 | 可用功能 |
| --- | --- |
| `admin` 平台管理員 | 全部後台功能，包括帳號權限、訪客個人明細、儲存／備份狀態及平台更新 |
| `game_manager` 遊戲管理者 | 全部遊戲的來源、匯入及紀錄、預覽、發布、版本切換與下架；看不到其他後台功能 |
| `analyst` 數據分析員 | 唯讀遊戲／訪客彙總、國家分佈及成績提交統計；看不到訪客 IP／帳號／活動明細、遊戲管理或平台系統資料 |
| `player` 普通玩家 | 遊玩與個人帳號功能，不能進入後台或使用任何管理 API |

平台管理員在「管理後台 → 帳號權限」搜尋已註冊帳號並變更角色，確認視窗會顯示授予的能力。角色變更在 API 上立即生效，已開啟的後台每三秒同步角色並清除舊角色畫面；切回視窗時也會更新。伺服器拒絕過期角色資料的修改，並保護最後一位平台管理員。角色分工不授予讀取其他玩家私人逐局成績或修改其密碼的能力。

玩家帳號為 3–32 個英文字母、數字或 `_ . -`，保留註冊時的大小寫；登入及帳號重複檢查不分大小寫，`Tommy` 與 `tommy` 是同一帳號。密碼為 12–256 字元，以 scrypt 雜湊保存。登入與註冊有 IP 頻率限制，session 有效期為 8 小時。登入後會保存遊戲開啟次數及估計活躍時間；接入 SDK 的遊戲也會保存逐局成績與最佳成績排行榜。帳號選單的「我的遊戲生涯」連到 `/players/:username`，逐局成績與進步趨勢只有本人可查看。此版不提供雲端進度存檔。

帳號選單的「帳號設定」位於 `/settings/account`，可驗證目前密碼後修改密碼或登出其他裝置。修改密碼會撤銷所有舊 session，為本裝置重新建立 session，其他裝置需重新登入；單獨登出其他裝置會保留目前 session。設定中的其他登入數量以有效 session 計算，同一裝置可能有多個 session。

生涯預設為 `public`，公開遊戲、最佳成績、開啟次數、完成局數、活躍時間與最近遊玩時間。`limited` 只公開遊戲與最佳成績，隱藏活動次數及時間；`private` 只有本人能查看生涯。本人始終可查看完整資料。**排行榜成績與玩家名稱仍公開**，生涯設定不會移除已提交的排行。修改密碼與撤銷其他 session 有每帳號限流，重新登入不會繞過限制。

登入後大廳顯示「最近遊玩」與「我的收藏」，可直接再次開玩。最近遊玩依已保存的開啟記錄排序，同款遊戲只顯示一次，最多 12 款；收藏可從遊戲目錄或詳情頁加入／取消，保存在帳號中並跨裝置同步。這兩個清單只有本人可查看，只顯示目前上架的遊戲；下架不刪除既有收藏，再次上架時會重新顯示。訪客仍可直接遊玩，收藏需先登入。

遊戲大廳沿用管理工作台的淺色品牌綠，提供歡迎摘要、搜尋與分類工具列及圓角遊戲卡片。桌面以多欄呈現，手機改為單欄；搜尋、分類、排序及收藏操作維持原有流程。

iPhone 玩家可按播放器工具列的「加入主畫面」查看安裝指引：用 Safari 的分享選單選擇「加入主畫面」，保留「作為 Web App 開啟」（若有），再從 Playroom 圖示啟動、選擇遊戲並按全螢幕。主畫面版本可移除瀏覽器網址列與工具列；一般瀏覽器的沉浸模式不能強制移除它們。系統狀態列與手勢區仍可能保留，平台會讓遊戲區域避開安全區。主畫面版本可能需要重新登入，本機遊戲存檔不保證與瀏覽器共用；安裝不提供離線遊玩或存檔搬移。

首位平台管理員由主機上的 `npm run admin:init -- admin` 初始化，之後可在帳號權限頁指派其他管理員。如果玩家已使用同名帳號，初始化時需選另一個管理員名稱。既有 schema v1–v8 資料庫會自動升級至 schema v9，保留帳號、密碼、角色、session、遊戲、生涯及收藏資料；既有 `admin` 保留完整權限，不需重新初始化。部署前先用原版備份指令保留資料；schema v1–v9 備份都能還原，新版備份也包含帳號公開範圍設定、成績提交指標、備份狀態、訪客記錄、GitHub 常用帳號、來源檢查、匯入批次及版本預覽確認。回退至不支援 v9 的舊平台時須還原升級前備份，不能直接開啟升級後資料庫。

## 本機啟動

需要 Node.js 24+。預設平台網址為 `http://localhost:3000`，遊戲來源為 `http://127.0.0.1:3001`。請使用 `localhost` 開啟平台；兩者刻意使用不同主機名稱來隔離 Cookie。

```sh
npm ci
npm run build
npm run admin:init -- admin
npm run demo:seed
npm start
```

`admin:init` 會要求輸入隱藏的密碼，至少 12 字元。也接受 `ADMIN_PASSWORD` 環境變數以便自動化；完成後應移除該變數。既有管理員不會被覆寫。初始化與範例資料指令應在平台停止時執行。

開發時執行 `npm run dev`，使用 `http://localhost:5173` 開啟網頁，API 在 3000，遊戲在 3001。Vite 的 API 代理保留瀏覽器的 Host，讓後端驗證平台主機名稱；使用 `127.0.0.1:5173` 或直接以 `127.0.0.1:3000` 呼叫 API 會得到 421，不能用遊戲來源的主機名稱開啟平台。若設定 `.env`，開發時使用 `PLATFORM_ORIGIN=http://localhost:5173`；直接執行正式建置的 `npm start` 時使用 `http://localhost:3000`。修改環境變數可改用其他連接埠；`PORT` 與 Vite proxy 目標、Vite 連接埠與 `PLATFORM_ORIGIN`、`GAMES_PORT` 與 `GAMES_ORIGIN` 必須對應更新。Vite 的 proxy 目標預設為 3000。

範例有「光點反應」與「色彩尋蹤」兩款可玩遊戲；v1.2.0 已接入帳號成績、`classic` 排行榜與管理預覽 SDK 診斷，同時保留瀏覽器本機最佳分數。既有本機最高分不會匯入帳號。停止平台後重新執行 `demo:seed` 可安裝並發布新範例版本，原有版本檔案保留；沿用 `classic` 的帳號最佳成績仍保留。正式環境不會自動加入或更新範例。

僅供本機試用的快速初始化可執行 `npx tsx scripts/preview-setup.ts`：它建立隨機管理員密碼，寫到被 Git 忽略且不會由網站提供的 `data/local-admin.txt`，並加入範例遊戲。正式部署請使用上面的互動式初始化。

## 管理工作台

後台採用淺色品牌綠工作台，桌面左側導覽、手機抽屜導覽按角色顯示功能。平台管理員及遊戲管理者預設開啟「遊戲更新」，分析員開啟「營運概況」。來源加入、開發者探索、封存／恢復及更新發布在同一列表處理。

「遊戲與版本」提供名稱、遊戲 ID 與 repository 搜尋，上架／待發布篩選及名稱／最近匯入排序，預設每頁 20 款，可選 50／100 款。點選「管理版本」開啟右側詳情，手機使用全螢幕詳情；版本可搜尋、每頁 10 筆。預覽、發布、回退、下架及校驗資訊都保留。切換後台頁面、刷新資料或關閉操作視窗不重置列表條件；離開後台後重置。首次發布仍須人工預覽確認。

## Docker 部署

需要 Docker Engine + Compose v2，以及自行管理的 HTTPS 反向代理與兩個不同主機名稱，例如 `play.example.com` 和 `games.example.com`。平台不再部署 Caddy，也不負責 DNS 或 TLS 憑證。

1. 將 `.env.example` 複製為 `.env`，填入 `PLATFORM_ORIGIN=https://play.example.com` 與 `GAMES_ORIGIN=https://games.example.com`，不要加結尾 `/`。
2. 執行以下指令建置、建立管理員與啟動服務。

```sh
docker compose build
docker compose run --rm --no-deps app npm run admin:init -- admin
docker compose up -d
docker compose ps
```

容器以 HTTP 提供後端，僅發布至主機的 `127.0.0.1:3000`（平台）及 `127.0.0.1:3001`（遊戲）；不佔用 80/443。主機上的 Nginx 負責對外 HTTPS，並保留正確的 Host。`NODE_ENV=production` 仍要求兩個公開 origin 使用 HTTPS，保持 Secure Cookie 與來源驗證。設定範本及切換步驟見 [Nginx 部署指南](docs/reverse-proxy.md)。不要把 `.env`、資料目錄或 GitHub token 提交到版本庫。

可選的範例初始化應在 app 尚未啟動時執行：

```sh
docker compose run --rm --no-deps app npm run demo:seed
```

資料保存在 `playroom-data` named volume；TLS 憑證由你的反向代理另行管理。重建或重啟容器不會清除資料；**不要執行 `docker compose down -v`**，除非確定要刪除 volumes。

一般更新：先備份，再執行 `docker compose up -d --build`。資料庫使用 `PRAGMA user_version` 追蹤 migration，啟動時自動建立或升級至 schema v9；讀到較新 schema 的舊版程式會拒絕啟動。此版本只有單個 app 實例，不應增加 replicas。

## 平台 OTA 更新

另提供 `compose.ota.yaml` 啟用獨立更新服務。admin 可在「平台更新」檢查指定 GitHub 分支的新提交、確認部署、查看進度及失敗紀錄。新映像先建置與測試，再停止 app 做備份；健康檢查失敗時還原備份至新 volume 並啟動舊映像。帳號與遊戲資料不會因映像替換而清除。

部署設定與安全邊界見 [平台 OTA 更新指南](docs/platform-updates.md)。此功能只更新 app，基礎設施與 updater 的變更需在主機上手動維護。未啟用更新服務的本機版會顯示未設定狀態。

## 營運概況

管理後台提供最近 7 天／30 天的營運概況。統計依 UTC 日期，從期間第一天 00:00 至目前時間，包含今天。

頁面以摘要卡區分訪客流量與登入玩家活動，搭配每日頁面瀏覽／遊戲開啟趨勢圖、熱門遊戲、成績提交及平台運作卡片。每日統計可展開查看完整數值；具明細權限的角色可展開「訪客活動記錄」使用原有篩選與分頁。

訪客統計包含匿名訪客與登入玩家，顯示獨立訪客、頁面瀏覽、遊戲開啟、每日趨勢、國家／地區分佈及前 10 款訪客熱門遊戲。活動明細每頁 25 筆，可依國家、完整 IP、遊戲 ID、活動類型或點選訪客編號篩選，記錄時間、IP、國家、當時登入帳號、頁面路徑、遊戲名稱／版本、來源網站 hostname 與 User-Agent。IP 使用 Fastify 按可信代理設定解析的 `request.ip`，忽略瀏覽器傳入的 IP／國家欄位及國家 headers；反向代理應按 [Nginx 指南](docs/reverse-proxy.md) 覆寫 X-Forwarded-For。

訪客以獨立的 host-only HttpOnly／SameSite=Strict Cookie 識別（production 加 Secure 與 `__Host-`），每次活動續期 30 天，資料庫只存識別 token 的 SHA-256。登入／登出可保持同一瀏覽器的訪客身分；不同裝置、清除或停用 Cookie 會再次計數，不等同實際人數。記錄保留 90 天，啟動及每小時清除逾期資料；既有備份仍包含建立快照當時的記錄。只記錄已知平台頁面的 pathname，不保存 URL query／fragment、完整來源 URL 或預覽 token。後台角色活動、後台頁面、預覽、健康檢查與資源請求均不納入。遊戲 iframe 載入後才記開啟，包含匿名及無 SDK 遊戲，不代表完成一局；統計依賴瀏覽器送出事件，不能用來證明真人或阻止偽造活動。資料從功能上線後開始累積，不能回補以往匿名瀏覽。

國家／地區使用 [geoip-country](https://github.com/sapics/geoip-country) 隨套件提供的本機資料庫推算，支援 IPv4／IPv6，查詢不向外部服務傳送訪客 IP；內網、無資料地址或查詢失敗顯示未知。VPN、代理或資料庫版本會影響推算。同一訪客在多個國家活動時會分別納入，國家訪客數不可直接相加。GeoIP 資料庫需隨套件更新並重建／部署（`npm install geoip-country@latest`）；遵循套件內 LICENSE／EULA 的資料更新要求。`geoip-country` 的 `ip-address` 依賴覆寫為修正版 10.7.3，以避免舊版已知漏洞。This product includes GeoLite2 data created by MaxMind, available from [MaxMind](https://www.maxmind.com/).

登入玩家指標另外顯示有開啟遊戲、回報心跳或完成局次的登入玩家數、開啟次數、完成局數，以及按開啟次數排序的前 10 款熱門遊戲。匿名訪客與預覽不計入帳號指標，已下架遊戲的歷史活動仍保留。生涯公開範圍不影響按角色限制查閱的統計與活動明細；`/api/v1/admin/visitors`、`/api/v1/admin/visitors/records` 每次查詢均驗證對應權限。

成績提交統計將伺服器收到的有效帳號／session 局次提交區分為 `success`、`rejected` 與 `server_error`，並顯示每日次數及保存失敗率。重複提交與重試都會再次計數，完成局數則只計已保存的局次；離線或未到達伺服器的失敗無法納入。指標從此功能上線後開始累積，不推算既往提交失敗。

儲存空間顯示平台資料用量、其中遊戲檔案用量，以及資料所在磁碟的總容量／可用空間。結果最多快取 30 秒，不追蹤符號連結，無法讀取時顯示「未知」。最近備份顯示平台備份指令記錄的 `never`／`running`／`success`／`failed` 狀態與最近成功時間；不代表目的地檔案仍存在或可用。

## 發布遊戲

1. 開發者在自己的公開 GitHub repository 開發遊戲，產出可直接用瀏覽器開啟的靜態檔案。
2. 在成品根目錄放置 `game.json`，入口與資源皆使用相對 URL。
3. 建立附有 `game.zip` 的 GitHub Release。
4. 管理員在「遊戲更新 → 加入來源」保存各位開發者的 GitHub 帳號或組織，探索公開 repositories、搜尋已載入清單並勾選批量加入；也可一次貼上多行 `owner/repository` 或 GitHub repository 網址。
5. 在「遊戲更新」勾選新版，一次確認版本清單並批量匯入；再選取待發布版本連續預覽，按「確認通過並看下一款」，最後選取已確認版本一次批量發布。單款匯入、發布與歷史版本回退仍可使用原有入口。

平台只列出最近 100 個非草稿 Releases，也顯示 prerelease 標籤。缺少唯一 `game.zip` 或 tag 格式不符的 Release 不能選取。預設選取按發布時間排序的最新可匯入正式版；若該 Release 已匯入，不會自動推薦更舊版本，其他未匯入版本與預發布版可手動選取。可選的 `GITHUB_TOKEN` 只在伺服器端存取 GitHub API，下載公開附件不會轉送 token。沒有 GitHub 連線時，已匯入遊戲仍可遊玩。

來源管理已整合到「遊戲更新」，支援搜尋、開發者、更新狀態及使用中／已封存篩選，每頁 25 筆，跨頁及跨篩選選取會保留。檢查、封存及恢復可逐款或批量操作；確認視窗列出涉及來源，各操作顯示實際可處理數量。手動檢查及加入最多同時發出 3 個請求，Release 檢查結果和時間保存在資料庫；檢查失敗保留上次成功結果並顯示錯誤。探索每次載入最多 100 個 repositories，搜尋範圍為已載入清單，可按「載入更多」擴大搜尋。封存來源只停止一般管理及批量檢查，不下架或刪除遊戲；匯入中的來源須等完成後封存。移除常用帳號不影響已加入來源。

每批最多 100 款，每個項目獨立回報；同一 UUID requestId 的匯入批次提交可安全重試，相同等待中任務沿用，已匯入 Release 跳過。批次頁保存所有項目，不受 overview 最近 50 筆任務限制；關閉視窗不停止已加入佇列的匯入，重啟則將未完成任務標為中斷，可批量重試。匯入不會自動上架，仍須逐款預覽確認，但已確認版本可一次批量發布。平台管理員及遊戲管理者可使用來源及批次 API，修改操作沿用 Origin／CSRF 保護。

伺服器預設每小時檢查所有未封存來源；進入後台時沿用五分鐘內的成功結果，其餘來源自動檢查，「立即檢查」可強制重新檢查。`GAME_RELEASE_CHECK_INTERVAL_SECONDS` 可調整背景檢查間隔（預設 3600 秒）。背景和手動檢查共用最多三個請求，相同來源與正在進行的整輪檢查不重複執行。GitHub 限流時依回應暫停，到期後連同先前被限流的來源自動重試，成功後清除錯誤；暫停期間保留上次成功清單。Release 檢查使用 ETag，304 回應沿用原清單。背景只檢查，不自動下載或上架。更新頁預選最新有效正式 Release，待發布選單只列出高於目前版本的未發布版本，較新的預發布版需手動選擇；未發布舊版不列為待更新，批量發布拒絕降版。已公開歷史版本的回退在「遊戲與版本」操作。

預覽確認是管理者對實際驗收的聲明，載入成功或 SDK 連線不會自動確認。確認者及時間按遊戲版本保存，管理者可共用、撤銷，刷新或重啟不會清除；新版本需重新確認。首次發布版本的單款與批量 API 都要求已確認；既有公開版本可直接回退或重新上架。批量發布逐款回報成功、略過及失敗，已是目標版本時略過；目前版本或上架狀態若被其他管理者修改，該款會拒絕發布，需刷新並重新確認。既有待發布版本升級後預設未確認，原有公開版本維持原狀。

每個 repository 對應一個遊戲 ID。更新時保留 ID、提高版本號，發布新 Release。匯入過的 `id + version` 不可覆寫，即使 GitHub 附件被替換也不會改寫平台上的成品。

在版本選單選擇舊的已發布版本，再按「回退到此版本」，即可切換大廳顯示的版本。遊戲保持上架時，過往已發布版本的資源仍可存取，讓已開啟的遊戲繼續運行；下架會封鎖該遊戲所有公開版本的新資源請求。已經載入記憶體的遊戲無法遠端撤回。

完整接入規格見 [遊戲開發指南](docs/game-development.md)。

管理員預覽提供 SDK 診斷面板，顯示連線、遊戲版本、榜單規則及最近 80 筆局次／成績／錯誤事件，可清除事件或重新開始。支援診斷的新 SDK 在預覽建立記憶體內模擬局次並驗證成績，完全不寫入遊玩記錄、生涯或排行榜；舊 SDK 會提示更新，沒有 SDK 時顯示未連線。診斷不能代替實際玩法與裝置驗收。

遊戲 repository 可使用 [Release workflow 範本](templates/game-release.yml)，將 `GAME_DIR` 設成成品目錄，並按需要加入遊戲的安裝／建置步驟。範本取得平台 `main` 的最新工具，以 Node 24 完成打包及完整 ZIP 驗證，通過後才建立 Release；規格、資源、路徑或大小檢查失敗會停止發布。既有遊戲 repository 需自行更新其 workflow，平台中的範本變更不會自動同步過去。

## 備份與還原

備份包含 SQLite snapshot、snapshot 引用的所有版本檔案，以及 SHA-256 檔案清單。版本檔案不可修改，因此可在服務運行時備份；未完成匯入不包含在內。備份會清除 session 與預覽授權，還原後需重新登入。

schema v9 備份保留帳號公開範圍設定、成績提交指標與訪客記錄。源資料庫只有在快照、版本檔案與雜湊清單全部完成後，才將本次備份標示為 `success`；失敗會保留最近成功時間並記錄 `failed`。快照擷取時本次備份仍在進行，因此快照中的 `running` 會轉為 `failed` 並提醒重新備份，不假造尚未完成的成功紀錄。這個提醒不代表完整且驗證通過的備份損壞；還原後重新執行備份即可更新狀態。

本機備份：

```sh
npm run backup -- backups/2026-10-04
```

Docker 備份（`BACKUP_DIR` 預設為主機的 `./backups`）：

```sh
mkdir -p backups
# Linux 上讓容器內 UID 1000 可寫入備份目錄；僅針對此新建目錄。
sudo chown 1000:1000 backups
docker compose exec app npm run backup -- /backups/2026-10-04
```

備份目標必須是尚不存在的目錄。請將完整備份另存到其他裝置，並限制存取，因為其中包含管理員密碼雜湊。

還原只接受空的資料目錄／新 volume，拒絕覆寫既有資料。先停止 app；保留原 volume，再還原到新 volume：

```sh
docker compose stop app
DATA_VOLUME_NAME=playroom-restored docker compose run --rm --no-deps app npm run restore -- /backups/2026-10-04
# 將 .env 的 DATA_VOLUME_NAME 改為 playroom-restored，再啟動。
docker compose up -d
```

PowerShell 本機還原範例：

```powershell
$env:DATA_DIR = '.\data-restored'
npm run restore -- backups/2026-10-04
npm start
```

還原前會驗證所有備份檔案雜湊、資料庫完整性及入口／封面是否存在。反向代理設定、TLS 憑證、`.env` 及 OTA 狀態不在平台資料備份內，請另外安全保存。

## 安全與維護邊界

- 平台預期接收可信任合作開發者的遊戲；不提供任意使用者上傳或伺服器端程式碼執行。
- 平台與遊戲分開主機名稱、Fastify listener 及路由。遊戲來源沒有管理 API，管理員 Cookie 是 host-only、HttpOnly，正式環境使用 Secure 與 `__Host-` 前綴。
- 修改 API 必須有正確 Origin；登入後另外驗證 CSRF token。登入限制為每 IP 15 分鐘最多 10 次，註冊最多 5 次。公開註冊只建立玩家，管理 API 逐次檢查資料庫中的 admin 角色。
- 每包最多 64 MiB、解壓後 256 MiB、10,000 個 ZIP entries，拒絕越界路徑、大小寫重複路徑、符號連結與加密檔案。下載最多 120 秒，只允許 GitHub 及其指定附件主機。
- 同時只處理一個匯入，最多 100 個等待及處理中任務。重新啟動後，中斷任務會標示失敗，需要重新提交。
- 預覽 URL 是 15 分鐘有效的 bearer grant，只授權一個版本，含相對資源路徑。知道連結的人可在期限內預覽；勿分享。預覽回應不快取，遊戲資源 listener 不記錄 URL，避免 token 進入日誌。
- 所有遊戲共用遊戲來源，可共享該來源的瀏覽器儲存空間；這不是遊戲之間的安全隔離。請為各遊戲的 localStorage keys 加上自己的 ID。
- 正式版沒有自動刪除歷史版本。需監控主機剩餘磁碟空間，並定期備份。健康檢查為 `/api/v1/health`；服務日誌可用 `docker compose logs --tail=100 app` 查看。

若斷電恰好發生在檔案移入版本庫與資料庫登記之間，可能留下未登記的版本目錄。停止 app、備份資料後，確認該 `id + version` **不在**後台或資料庫 `versions` 表，再將對應的 `data/games/<id>/<version>` 移到資料目錄之外保留，便可重新匯入。不要移動已登記的版本。

## 檢查與專案結構

```sh
npm run typecheck
npm run build
npm test
npm run test:e2e
npm audit
```

瀏覽器測試預設使用已安裝的 Chrome。Linux CI 或沒有 Chrome 時：

```sh
npx playwright install --with-deps chromium
PLAYWRIGHT_CHANNEL=chromium npm run test:e2e
```

E2E 使用臨時資料庫與測試用 GitHub adapter，不會更動本機平台資料或發布 GitHub Release。測試涵蓋真實 ZIP 匯入與完整 UI；GitHub adapter 另測限流、下載中斷與下載來源限制。測試用帳號只存在臨時資料庫中。

| 目錄                | 用途                                      |
| ------------------- | ----------------------------------------- |
| `client/`           | React 介面與樣式                          |
| `server/`           | API、遊戲資源、匯入、登入、CLI 與備份還原 |
| `shared/`           | 遊戲 manifest 驗證與共用 TypeScript 型別  |
| `examples/starter/` | 完整靜態遊戲範本與實際遊戲封面            |
| `scripts/`          | 打包、驗證、封面截圖與 Docker smoke test  |
| `templates/`        | 開發者可複用的 GitHub Actions workflow    |
| `tests/`            | 後端整合、安全邊界與 Playwright 測試      |

遊戲 SDK 與榜單設定見 [遊戲開發指南](docs/game-development.md)，平台 API 與後台細節見 [平台參考](docs/platform-api.md)。生涯摘要依帳號公開範圍設定顯示，排行榜仍公開玩家名稱、最佳成績與排名；訪客及管理預覽不產生帳號記錄。活躍時間以大廳前景焦點與 15 秒心跳估計，中斷超過 30 秒不補算；同時在多裝置遊玩可能重疊計時。排行榜用於休閒比較，前端回報分數無法杜絕作弊。後續可加入雲端進度存檔與逐款遊戲的伺服器驗證；多人遊戲仍需獨立後端。

本人生涯的「我的進步」按遊戲及榜單顯示最近 30 局趨勢、逐局突破標記、歷來最佳與突破次數。突破以全部歷史成績比較，首次成績是起點，同分不算突破；同一榜單的版本合併追蹤，不同榜單分開計算。趨勢與逐局資料只有本人可見，下架後仍可查閱。排行榜也顯示距離並列前一組名次的分數差，支援分數越高／越低越好的榜單。
