# 07 — 匯入中斷恢復與版本保留規則

狀態：已完成；本機與 Linux Docker／CI 同等檢查通過。優先程度：中。

## 規劃時現況與目標

安裝版本先將 staging 檔案移至正式目錄，再交易寫入資料庫。一般例外會清理，但程序在兩步之間中斷可能留下未登記版本目錄。目前啟動把未完成匯入標為失敗，README 指示人工檢查及移走孤立目錄。

目標是讓安裝有可辨認、可重複執行的恢復程序，不要求管理者直接判斷哪些正式目錄可以刪除。版本保留規則也需先定義，避免未來清理破壞排行榜、生涯或備份。

## 子任務

- [x] **07.1 列出安裝階段及不變條件。**涵蓋下載、驗證、準備安裝、檔案移入、資料庫登記、任務完成；已登記版本不可覆寫，匯入不自動發布。
- [x] **07.2 建立持久化安裝日誌。**在檔案移入前保存工作 ID、遊戲／版本、來源、預期位置及驗證資訊；路徑由可信任根目錄與已驗證識別建立，不接受任意外部路徑。
- [x] **07.3 定義重啟核對表。**逐項判斷日誌、staging、正式目錄與版本記錄的組合；完整已登記版本補正任務結果，完整但未登記成品只有再次驗證通過才補登記。
- [x] **07.4 隔離不確定資料。**內容不符、校驗失敗或來源不明的成品移到專用隔離區，保留原因與工作關聯，不自動刪除，也不提供為公開遊戲資源。
- [x] **07.5 保證恢復可重入。**同一修復執行多次不重複建立版本、不覆寫已登記檔案、不改變目前上架版本；恢復本身中斷後可再次核對。
- [x] **07.6 提供受控維護入口。**先提供只讀診斷／dry-run 報告，再提供針對已識別任務的修復命令。維護操作遵守現有資料目錄鎖，不可與正常匯入互相競爭。
- [x] **07.7 定義版本引用與保留。**列出目前上架、既有公開資源、有效預覽、安裝任務、排行榜／生涯與備份對版本檔案及 metadata 的依賴。分清「移除資源」與「刪除版本記錄」。
- [x] **07.8 建立清理候選報告。**先只提供可回收項目、空間與阻擋原因，不直接加入自動清理。既有公開版本在遊戲上架期間仍可能被開啟的頁面使用，不得因不是 activeVersion 就刪除。
- [x] **07.9 更新備份與操作指南。**備份只納入一致且已登記的版本，說明安裝日誌、隔離區的處理方式；以新診斷流程取代容易誤操作的手動刪目錄步驟。

## 驗證與驗收

- [x] 在檔案移入前、移入後／登記前、登記後／任務完成前注入中斷並重啟。
- [x] 完整成品可恢復，損壞或不確定成品被隔離，不會公開或覆寫既有版本。
- [x] 重複執行恢復及恢復途中再次中斷後，最終狀態一致。
- [x] 已有遊戲的上架版本及可遊玩性不受失敗匯入影響。
- [x] 路徑越界、符號連結及同名目錄衝突不造成資料目錄外的檔案操作。
- [x] 匯入與備份同時進行時，備份引用的每個版本均完整；還原不需要依賴遺失的 staging。
- [x] 保留規則不使歷史榜單、生涯、既有有效預覽或仍應可存取的公開版本失效。
