# 02 — 存檔格式相容性與遊戲回退保障

狀態：已完成，相關驗證與後續完整整合驗證通過。優先程度：高。

## 規劃時現況與目標

`cloud_saves` 以玩家與遊戲為主鍵，只保留目前一份存檔。`revision` 已提供樂觀鎖，`formatVersion` 由遊戲自行驗證與遷移。平台允許回退已公開遊戲版本，但不知道該版本能否讀取目前的玩家存檔。

目標是讓遊戲更新、舊分頁繼續執行及版本回退都不能靜默破壞進度；不把遊戲版本回退誤當成玩家資料自動回退。

## 子任務

- [x] **02.1 定義格式契約。**在遊戲接入規格定義可讀格式、寫入格式，以及遇到不支援格式的行為；以版本 Manifest 保存宣告。存檔 revision、formatVersion、gameVersion 各自維持不同用途。
- [x] **02.2 定義既有遊戲相容方式。**未宣告能力的既有遊戲標示為「相容性未知」，保留原行為，不虛構支援範圍；新宣告欄位與 Manifest schema 升級策略由 01 一併處理。
- [x] **02.3 在伺服器檢查寫入資格。**依提交的已發布遊戲版本及存檔宣告檢查格式；保留 revision、requestId、帳號隔離與速率限制。只宣告支援範圍不能取代遊戲內 data 驗證。
- [x] **02.4 防止舊分頁降級覆寫。**新遊戲已遷移存檔後，仍開啟的舊版若不支援新格式，讀取時明確提示，寫入時拒絕，不能靠重新取得 revision 繞過限制。
- [x] **02.5 保留遷移前快照。**在首次成功改變 formatVersion 的交易中保存舊資料與必要版本資訊；快照寫入失敗時整個遷移寫入失敗。重試不能重複產生同一次遷移快照。
- [x] **02.6 整合發布／回退檢查。**後台顯示目標版本與既有存檔的相容性及受影響情況。已知不相容時拒絕直接回退；未知時不能顯示已驗證相容。單款與批量共用同一檢查。
- [x] **02.7 定義恢復程序。**提供本人驗證後的明確恢復操作或受控維護流程；恢復建立新的 revision，不倒退 revision，不自動覆寫其他裝置剛保存的資料。管理角色不得因此取得閱讀玩家私人存檔的權限。
- [x] **02.8 納入備份與保留政策。**快照納入完整備份、還原及容量統計；實作前記錄快照保留上限與淘汰規則，未定義前不得上線自動刪除。

## 驗證與驗收

- [x] 格式 1 升級格式 2 後，資料可恢復，遷移前快照完整。
- [x] 舊版不支援格式 2 時，不能把預設進度或格式 1 覆蓋回去。
- [x] 已宣告可讀格式 2 的回退目標可正常使用存檔；不相容目標被拒絕並提供原因。
- [x] 同格式寫入維持現行行為，無存檔仍回傳 null，讀取失敗不能當成沒有存檔。
- [x] 兩裝置競爭、回應遺失後重試、session 撤銷及恢復與保存並行均不遺失資料。
- [x] 預覽不讀寫正式存檔或快照；其他帳號與管理角色不能讀取私人進度。
- [x] 舊資料庫升級及備份還原保留目前存檔與快照。

## 依賴與文件

契約依賴 01，錯誤與發布衝突使用 06，新增表使用 05。同步更新遊戲開發指南、Manifest schema、SDK 型別／範例、發布文件及 `templates/game-agent-template.md`。

本項的保護先集中在平台雲端存檔。遊戲自行管理的 localStorage 仍需遊戲自行遷移，不能宣稱平台能恢復所有本機資料。
