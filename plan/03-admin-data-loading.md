# 03 — 後台 API 分頁與按需更新

狀態：已完成本輪實作與相關驗證；後續完整 CI 同等檢查／Docker 驗證通過，見 [最新進度](README.md#2026-10-11-最新進度)。優先程度：高。

## 規劃時現況與目標

後台每三秒取得 overview、完整來源列表及來源檢查狀態。overview 包含全部遊戲與歷史版本，遊戲／版本／來源列表主要在瀏覽器內分頁。`adminLibrary` 先取得所有版本，再逐遊戲篩選。

目標是讓單頁資料量有上限，查看一頁不需要讀取完整遊戲庫，刷新進度不重新下載所有 Manifest。

## 子任務

- [x] **03.1 建立測量基準。**以臨時資料建立例如 1,000 款遊戲、每款 20 個版本的 fixture，記錄 overview 回應大小、查詢與處理時間；不操作正式資料。
- [x] **03.2 拆開摘要與詳情。**新增後台遊戲列表、單款版本列表及版本詳情介面。摘要包含目前版本、最新匯入與待發布資訊；完整 Manifest 在詳情或預覽時取得。
- [x] **03.3 將列表條件移到後端。**遊戲、版本及來源 API 接收搜尋、篩選、排序與分頁參數，回傳當頁資料和總數。保留既有每頁大小選項，限制上限並使用唯一 ID 作為穩定排序的最後條件。
- [x] **03.4 移除隱性全量依賴。**更新候選、待發布判斷、批量選取、預覽佇列都不能再依賴完整 `AdminGame.versions`。候選摘要由後端共用規則產生，必要詳情按選取項目載入。
- [x] **03.5 保留跨頁選取。**選取狀態用來源／遊戲／版本 ID 保存；提交時由伺服器重新驗證權限、存在性與狀態，不信任已快取摘要。保留每批最多 100 項的限制。
- [x] **03.6 集中請求生命週期。**提供共用的讀取／刷新機制，處理去重、取消、錯誤、過期回應及 mutation 後刷新；切換條件後舊請求不能覆蓋新結果。
- [x] **03.7 分離輪詢。**進行中的匯入與檢查任務使用小型狀態介面；列表在進入、條件變更、操作成功或明確刷新時更新。隱藏頁面暫停非必要輪詢，回到前景補刷新，避免請求重疊。
- [x] **03.8 逐步替換 overview。**先加入新介面並遷移消費端，再移除未使用的全量欄位；同步測試與 API 文件。公開大廳 API 不在本項順便重寫。

## 驗證與驗收

- [x] 一頁遊戲資料不含其他頁的版本 Manifest；單一任務進度更新不讀取全遊戲庫。
- [x] 搜尋、篩選、排序、頁碼與空頁行為正確，修改或移除資料後不出現失效選取。
- [x] 跨頁／跨篩選的選取、批量匯入、連續預覽及發布維持既有語義。
- [x] 慢請求回傳順序顛倒時，畫面仍對應最新條件。
- [x] 後台角色撤銷後停止受限請求並清除舊資料；不能因快取保留越權內容。
- [x] 使用與基準相同的資料及環境比較回應大小和時間，記錄結果；主要驗收是讀取範圍受頁面大小限制，而非宣稱任意時間門檻。

## 依賴與交付

配合 04 拆分頁面與資料 hook；使用 06 的錯誤和衝突契約。交付分頁介面、前端資料管理、規模 fixture、對照測量與相關 E2E。無需引入 WebSocket 或分散式快取。
